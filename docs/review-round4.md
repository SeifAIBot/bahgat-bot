# Review Round 4 — Architecture, scalability, testing, CI/CD, deployment (2026-11-25)

Independent subagent review, fresh read of v0.4 + web research. No files edited. Reviewer did NOT read parallel round5 doc (one grep hit surfaced it, not read).

Verdict: bot will run, but architecture it claims is not architecture it has. ARCHITECTURE.md promises Clean Architecture, real plugin system, config-driven behaviour, durable inbox/outbox, /reload — none implemented. Most dangerous deployment finding: entire memory lives in data/bahgat.db, Render Free deletes that file on every redeploy/restart. Second: no git repository at all, so frequent updates have no version control, no rollback, no CI.

## Critical
- C1. No version control — git status fatal: not a git repository. No .github/, remote, tags. DEPLOY.md step 1 "push to private GitHub repo" never happened. No rollback, audit trail, PR review, CI impossible. Fix: git init, private GitHub repo, main branch protection, tag releases v0.4/v0.5, deploy from repo only. Add .venv/ to .gitignore — currently NOT ignored (.gitignore lists .env, data/, __pycache__, *.db, downloads/, voice/ only), first git add . would commit 74MB .venv.
- C2. Render Free will delete entire memory on every redeploy — all state (members, moods, grudges, provider_usage, processed_updates) in data/bahgat.db (memory.py:7, router.py:77, handlers.py:28). render.yaml free worker no persistent disk. Render Free ephemeral FS cannot attach persistent disk; local files lost on every spin-down; free Postgres expires 30 days. Every redeploy wipes memory/mood/grudge/quota. No backup (no sqlite3 backup API, Litestream, periodic copy). Fix: move state out before first deploy: Neon free Postgres (not Render own free Postgres, expires 30d) or Oracle Always Free VPS where disk is real. Until then at minimum startup backup copying bahgat.db to object storage (Backblaze B2 free 10GB / Tigris 5GB) on shutdown.
- C3. Handler is 241-line god function — documented layering inverted. _on_group_message_inner (~112-218) does dedup SQL, rate limiting, owner parsing, trigger gating, cooldown, typing, member CRUD, mood, grudge, intent, YouTube keyboard+callback download, search grounding, prompt assembly, LLM call, unknown-retry, verification, voice policy, sending. ARCHITECTURE.md says "Business logic or SQL in handlers prohibited" — handlers contain both. No services/ dir despite ARCHITECTURE naming one. Fix: extract services/message_pipeline.py orchestration + services/ for owner-control/rate-limit/voice-policy; handlers thin adapters validate update and delegate. Import-linter contract (handlers may not import sqlite3, brain.memory internals, tools.* directly) enforced in CI.
- C4. Plugin system not real. plugins/registry.py:8-12 load_enabled() grep never called anywhere. No plugin implements documented interface (can_handle(text, ctx)->bool, async handle(ctx)->dict): search_plugin run(query), youtube_plugin async run(url, audio_only) calls sync download() without await/to_thread, voice_plugin run(text) — three incompatible signatures. ARCHITECTURE.md lists fourth plugin memory_plugin.py which has NO file. config/plugins.yaml never read by any code path. Fix: implement for real — Plugin Protocol (can_handle, async handle), auto-discovery from plugins/, dispatcher in service layer trying plugins in plugins.yaml order, one test per plugin — or delete plugin claim from docs and plugins/ dir so next change doesn't build on fiction.
- C5. Sequential-by-default processing + blocking calls: one slow handler stalls every group. main.py:16 app.run_polling() no args; app.py:15-18 Application built with no concurrent_updates(). PTB default sequential, SimpleUpdateProcessor(max_concurrent_updates=1) unless concurrent_updates passed, every handler block=True unless otherwise. Into single queue: LLM calls seconds, voice.py:18-19 subprocess.run(ffmpeg, timeout=60) inside async def, YouTube downloads up to 300s (youtube.py:21) — to_thread frees loop but handler still awaited so queue waits. _rate_limit handlers.py:46-58 asyncio.sleep inside handler holding queue; at 20 msgs/min can sleep up to 60s, no other update anywhere processed. Fix choose one document in code: (a) concurrent_updates(8) + block=False on message handler + per-chat asyncio.Lock/Semaphore(1) replies ordered per chat; or (b) keep sequential but move long work (YouTube download, voice) to per-chat asyncio.Queue worker task handler returns immediately. Either way replace sleep limiter with per-chat send queue/token bucket.
- C6. "Config-driven behaviour" fiction — YAML loaded then ignored. core/persona.py load_persona() called once import (handlers.py:27 _PERSONA) never referenced again; only _EXAMPLES used. Editing persona.yaml (mood thresholds 30/70/90, decay_per_hour 10, voice rules) changes nothing — real values hardcoded mood.py (+40/-20/-5) and prompt.py (SYSTEM_BASE hardcoded not built from YAML). providers.yaml timeout_seconds, max_retries_per_provider, context_messages, simple_chat_model, hard_question_model never read by any .py — router hardcodes timeout=30 line 86 and 2 attempts; context limit 8 hardcoded handlers.py:156. rules.yaml never loaded; owner_id from env, owner commands hardcoded strings handlers.py:130-142, listed commands (reload, change mood, mute) unimplemented. README:35 and ARCHITECTURE.md:40 claim "reload with /reload (owner only)" — NO /reload handler exists. Fix: build system prompt, mood thresholds, router params from loaded YAML (single PersonaConfig/ProviderConfig dataclass validated Pydantic at startup), implement owner-only /reload re-reading YAMLs, or delete claims. Config that doesn't change behaviour worse than no config.
- C7. No CI, no lockfile, no reproducible builds. No .github/workflows/, pyproject.toml, setup.cfg, tox.ini, lockfile (uv.lock/poetry.lock/requirements*.lock none). requirements.txt yt-dlp>=2026.1.1 unpinned lower bound (future release can break bot on next Render rebuild); google-genai==1.30.0 never imported; tenacity==9.0.0 never imported (router hand-rolls retries); httpx==0.28.1 never imported directly (transitive via openai); pytest==8.3.4 ships in production image (dev dep). No pytest-asyncio, ruff, mypy, aiosqlite, .python-version. Fix: pyproject.toml + uv.lock (or pip-compile pinned requirements.txt), split dev deps requirements-dev.txt, .github/workflows/ci.yml running ruff check, ruff format --check, mypy, pytest --cov with floor, uv lock --check so CI fails stale lock.
- C8. No health check or observability on worker that cannot receive HTTP. render.yaml type worker — Render background workers outbound-only cannot receive inbound, no /health can exist, Render cannot health-check process. Dockerfile no HEALTHCHECK; docker-compose no healthcheck. main.py:10 logging.basicConfig(level=INFO) plain text no structured logs no correlation/update id; no metrics (latency, tokens, error rate per provider), no /stats owner command (still "not yet built" CHANGELOG), no heartbeat. Deadlocked event loop (blocking ffmpeg) looks "running" to Render forever — not crash so nothing restarts. Fix: write heartbeat timestamp (last successful poll + last reply) into DB (or file) every loop iteration; tiny separate web service or external uptime monitor reading log stream alerts when heartbeat stale >5 min. Structured logging JSON formatter update_id/chat_id every line + owner-only /stats reading provider_usage.

## Major
- M1. SQLite: new connection + full schema re-execution per call, all synchronous. memory.py:9-17 _conn() opens new connection runs executescript(schema.sql) (7x CREATE TABLE IF NOT EXISTS + PRAGMA journal_mode=WAL + CREATE INDEX) ON EVERY CALL. Per message: dedup 1 conn, get_member, save_member, add_message, recent_messages (4 conns) + router quota check/record (2-3 conns) = ~8-9 connections/message each opening/closing file. All sync sqlite3 from async handlers. voice.py:18 blocks ffmpeg up to 60s inside async def. Fix: one long-lived aiosqlite connection (single writer, timeout=30, WAL+busy_timeout), migrations once at startup, asyncio.to_thread (or create_subprocess_exec) for ffmpeg. Batch member read + mood write + history insert few round trips.
- M2. No migrations — schema no versioning. schema.sql no version table; "migration" is re-running CREATE TABLE IF NOT EXISTS every connection. Adding column no path (no ALTER TABLE tracking). Fix: schema_version table + numbered migration files migrations/001_*.sql applied once at startup in order; or yoyo-migrations/alembic.
- M3. Unbounded growth: tables and in-memory dicts never shrink. processed_updates NO pruning — 1 row/update forever (~365k rows/year at 1,000 msgs/day). _last_user, _send_count, yt_requests (handlers.py:31-33) module dicts no eviction. add_message (memory.py:48-60) runs DELETE ... WHERE id NOT IN (SELECT ... LIMIT 200) full-table scan ON EVERY INSERT. pinned_facts and outbox tables exist schema.sql never read/written (dead; ARCHITECTURE "outbox queue" false — no sweeper). Fix: prune processed_updates >48h via periodic JobQueue task not per-insert; replace per-insert prune with periodic cleanup; bound in-memory dicts TTL eviction; implement outbox+sweeper or delete table and doc claim.
- M4. run_polling() no arguments — four undecided behaviours. main.py:16 app.run_polling(). PTB v22.8 defaults: timeout 10s, allowed_updates=None, drop_pending_updates=False, bootstrap_retries=0. (a) allowed_updates=None receives all except chat_member/message_reaction — NEVER receives chat_member updates, cannot track joins/leaves, member list insult rule says must check. (b) drop_pending_updates=False after downtime bot answers flood stale "بهجت" messages at once. (c) bootstrap_retries=0 if Telegram briefly down at boot process exits crash-loops. (d) No stop_signals/close_loop. Fix: run_polling(timeout=30, allowed_updates=["message","callback_query","chat_member","my_chat_member"], drop_pending_updates=<explicit documented decision>, bootstrap_retries=-1). 30s long-poll standard.
- M5. No single-instance enforcement — second poller causes 409 Conflict. Nothing prevents running bot twice (local python main.py + Render worker). PTB/Telegram exactly one getUpdates consumer per token; second gets 409 steals updates. DEPLOY.md local-test steps no warning. Fix: startup lock (PID/lock file or SELECT...FOR UPDATE-style claim in DB) exits loudly if another instance polling; document DEPLOY.md never run local+Render same token.
- M6. Dockerfile and Compose not production-grade. Dockerfile 8 lines: runs as root (no USER), no HEALTHCHECK, unpinned base python:3.11-slim floating, no multi-stage, no tini/init (zombie yt-dlp/ffmpeg children accumulate), no PYTHONUNBUFFERED. docker-compose: no healthcheck, no user:, no resource limits (mem_limit/cpus), no log rotation, restart unless-stopped fine. Fix: FROM python:3.11-slim@sha256:<pinned> (or 3.12-slim), multi-stage, RUN groupadd/useradd app && USER app, COPY --chown=app:app, HEALTHCHECK CMD python -c "...check heartbeat file...", ENV PYTHONUNBUFFERED=1; Compose user "1000:1000", mem_limit 512m, healthcheck + logging max-size 10m. Note Docker HEALTHCHECK hitting HTTP impossible polling-only worker — heartbeat-file check instead (C8).
- M7. .env handling fragile, leaks operational state to group. core/config.py:5 env_file=".env" relative to CWD not project root — running python main.py elsewhere silently loads no .env. load_settings() lines 13-18 validates only token+owner; missing Gemini/Groq keys NOT failed at startup — router instead returns "يا عم، المفاتيح لسه متظبطتش..." INTO GROUP CHAT (router.py:148-149) leaking operational detail. core/config.py:10 still declares dead openrouter_api_key; .env.example still lists OPENROUTER_API_KEY and RENDER_EXTERNAL_URL (meaningless polling no webhook). Fix: resolve .env against Path(__file__).resolve().parents[1]; fail fast startup if any required key empty (log server-side only never to group); delete dead fields/stale example entries.
- M8. Shared mutable state no locks — safe today only by accident. No asyncio.Lock/Semaphore/thread-safe structure anywhere (grep). Mutated without locks: _last_send, _send_count, _last_user, yt_requests (handlers.py:31-33), CircuitBreaker.failures/open_until (router.py:48-63, no HALF_OPEN probe limit — after expiry ALL concurrent requests probe at once), BrainRouter._clients. yt_requests keyed by chat only: second user's YouTube request overwrites first's, on_callback never checks button-presser is requester. Safe today only because PTB processes sequentially (C5) — undocumented implicit guarantee. Moment concurrent_updates enabled to fix C5, all races: mood read-modify-write loses increments, yt_requests cross-wires, breaker miscounts. Fix: document sequential assumption in app.py OR remove assumption: per-chat asyncio.Lock, per-user mood atomic SQL (UPDATE members SET mood=MIN(100, mood+40) WHERE user_id=?), callback data opaque request id (store state server-side keyed by id, verify callback_query.from_user.id matches requester).
- M9. Graceful shutdown incomplete. app.py:9-12,19 _post_shutdown closes only LLM clients, assigned as attribute AFTER build() (app.post_shutdown=_post_shutdown) rather than Application.builder().post_shutdown(...) (fragile, not supported construction path). Nothing checkpoints SQLite WAL, cancels in-flight yt-dlp (up to 300s) or voice synthesis; Render SIGTERM then SIGKILL after grace can orphan yt-dlp child. Fix: builder post_shutdown(), shutdown hook cancels in-flight download/voice tasks with timeout, PRAGMA wal_checkpoint(TRUNCATE), logs clean stop. bootstrap_retries=-1 so failed start retries not crash-loop (M4).
- M10. Test coverage: riskiest code zero tests. tests/test_triggers.py literally assert True. 17 tests cover only pure functions (verify, prompt, router breaker, intent, insult_rules). handlers.py, app.py, main.py, memory.py, tools/*, plugins/*, core/config.py 0% coverage. No conftest.py, fixtures/mocks, pytest-asyncio (required test async handler), coverage gate, CI. Missing concrete cases: 1. Trigger matrix _should_reply mention/plain بهجت/reply-to-bot/no trigger/own message/private/edited. 2. Dedup same update_id twice -> exactly one reply (mocked Update+Message). 3. Rate limit 21st msg/min delayed; 1 msg/s spacing parts. 4. Split 5,000-char reply sentences -> 2 parts <=4,000; single 9,000-char word -> hard split (exists only x-string test, no sentence-boundary test). 5. Anonymous admin effective_user None -> returns without crashing. 6. Owner commands exact+punctuation variants pass; non-owner ignored; owner command without trigger still works. 7. Cooldown second msg same user within 3s dropped. 8. Callback different user pressing YouTube button rejected; second YouTube request doesn't overwrite first. 9. Router mocked AsyncOpenAI: simple Groq first, hard Gemini first; 429 rotates; 401 fails fast; empty content retries; breaker opens after 3 failures; quota-exhausted skipped. 10. Memory mood decay math (-10/h read, -5/message); prune keeps 200/chat; two concurrent save_member don't lose update. 11. Search _resolve_ddg decodes uddg; Lite fallback HTML 0; non-HTML returns "". 12. YouTube mocked subprocess.run -> correct file; playlist rejected; >50MB rejected; raw chat text (not URL) fails cleanly not passed to yt-dlp. 13. Voice ffmpeg failure -> text fallback; partial .ogg deleted on failure. 14. Config missing token -> RuntimeError startup; missing Gemini key -> fail fast (proposed). 15. Prompt guardrails present ordered before dynamic context; style examples injected; search instruction present. Fix: pytest-asyncio + conftest.py (fake Update/Context/Bot fixtures), handler tests mocked Application, coverage floor --cov-fail-under=50 to start rising, run suite in CI (C7).
- M11. Documentation drift — docs describe different bot. README:43 still "Gemini -> Groq -> OpenRouter :free (fallback 2)" removed v0.4; README Deploy "See docs/DEPLOY.md (to be added in deployment step)"; README Status "Token/owner ID/test group: waiting for Seif" though all three verified; ARCHITECTURE claims services/ layer, outbox queue, memory_plugin, /reload — none exist; CHANGELOG v0.4 claims "providers.yaml honoured" — grep proves routing fields never read. N2 Mood double decay: mood.py:15 -5 every non-insult message, memory.py:27-29 -10/hour on read; praised never True (handler always False); persona.yaml thresholds unused (C6). Fix one decay mechanism driven by persona.yaml, praised actually wired.
