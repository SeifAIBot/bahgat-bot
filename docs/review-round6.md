# Review Round 6 — Performance, free-tier cost, observability (2026-11-25)

Independent subagent review, fresh read of v0.4 + web research. No live LLM calls made; latency/token figures computed from code + published limits, labelled estimates.

## Verified free-tier numbers (web, 2026-11-25)
- Groq gpt-oss-120b and 20b: 30 RPM, 1,000 RPD, 8,000 TPM, 200,000 TPD per model per org. 120b ~500 tok/s, 20b ~1,000 tok/s.
- Gemini gemini-3-flash-preview: Google publishes no per-model free numbers; AI Studio per-project authoritative. Best third-party checks: 5 RPM, 250,000 TPM, 20 RPD. Other round-ups 10-15 RPM / 250-1,000 RPD. Treat 20 RPD as planning case until Seif reads aistudio.google.com/rate-limit. Preview model: billing enabled typically, more restrictive limits, deprecated with >=2 weeks notice.
- Gemini context caching: implicit caching ~75-90% off cached input on PAID tier, min prefix 4,096 tokens for Gemini 3 family. Free tier has no access.
- Telegram: 1 msg/s per chat, 20 msg/min per group, ~30 msg/s bulk; 429 carries retry_after.

## Measured prompt sizes (reviewer ran build_system_prompt)
- SYSTEM_BASE 570 chars ~190 tokens (len//3). Full system prompt no search: 1,107 chars ~369 tokens (len//3) / ~550 realistic Arabic. With search (1,500-char excerpt): 2,735 chars ~911 tokens (len//3) / ~1,370 realistic. History 8 msgs ~320-480 tokens. Output typical 150-300 tokens + invisible reasoning tokens.
- Per-call totals estimate: plain chat ~1,000-1,400 tokens; search ~1,600-2,300; search+unknown-retry ~3,200-4,600; worst case retry+fallback ~4 LLM calls per user message.
- Replies/day: Groq 120b alone plain chat ~150/day; search ~105/day; with unknown-retry ~50-75/day. Groq 120b+20b together (caps per model) ~300 chat replies/day if simple chat routed to 20b. Gemini planning case 20 RPD: 20 hard/search replies/day.

## Critical
- C1. Hard questions go to Gemini first — scarcest pool burned first (router.py:150-158, handlers.py:180 hard=intent==search). Every search + unknown-retry hits Gemini before Groq. At 20 RPD only 20 search/day, then 429 + wasted slow call + fallback anyway. Fix: Groq first for everything, Gemini only on Groq failure or narrow class; route search synthesis to Groq 20b; reserve Gemini <=20/day by hard counter in provider_usage (stop before 429, e.g. at 15/day, surface in /stats). Verify Seif's real Gemini numbers in AI Studio.
- C2. Groq 429 marks provider dead 1 hour even for 60s per-minute limit (router.py:105-118 _mark_exhausted seconds=3600). Groq has TPM 429 (clears <=60s) vs TPD 429 (midnight). Fix: parse 429 body/headers; Retry-After <=120s -> ban exactly Retry-After; only until midnight UTC when error text indicates daily quota; log kind.
- C3. No successful LLM call logged with latency/tokens — quota invisible until failure (router.py:171-185 success path only _record_usage to SQLite, nothing reads it; handlers.py:201 logs provider/intent/mood only). _quota_exhausted swallows all exceptions and returns False. Fix: one structured JSON log line per LLM call {provider, model, latency_ms, ttft_ms, tokens_in, tokens_out, reasoning_tokens, finish_reason, retries, status, error_code} in finally; owner-only /stats reading provider_usage (requests+tokens today per provider, estimated remaining replies, error counts, p50/p95 latency if llm_calls table added); log _quota_exhausted DB errors.
- C4. Non-streamed replies + typing dies after 5s (handlers.py:149-151 single send_chat_action, router.py:170 non-streaming). Normal LLM 2-10s, search 4-12s, retry 8-20s, fallback storm up to ~2 min. Fix cheap: asyncio task re-sends typing every 4s until reply ready, cancelled on send. Then stream final reply editing progressively every ~1-2s / ~100 chars; record TTFT and total separately.
- C5. max_completion_tokens=4000 invites long replies burning daily pool (router.py:168; prompt says short, code allows 4,000 tokens ~12,000 chars ~3 Telegram messages). One reply can eat 2% of Groq day. Fix: cap output 400-600 tokens group chat (600 search synthesis), keep 4,000 only for explicit long-answer path.
- C6. YouTube: every repeat re-downloads/re-uploads up to 50MB — no file_id cache (tools/youtube.py:13-32, handlers.py:220-245, schema.sql no youtube_files table). Fix: youtube_files(url_or_video_id, audio_only, file_id, size, created_at); lookup file_id first and reply_video/reply_audio(file_id); store file_id from sent message; in-flight map keyed (query, audio_only) so concurrent duplicates await same download. Minutes -> <1s on hit.

## Major
- M1. Search fully sequential, throws away 4 of 5 results (tools/search.py:24-47, handlers.py:89-97). DDG GET + page GET sequential, worst 40s before LLM, only result #1 read (live test: result #1 was YouTube channel page ~200 chars boilerplate). Fix: fetch top 3 pages in parallel asyncio.gather, keep first 2 with real text >200 chars, skip youtube/tiktok boilerplate, truncate excerpt ~800 chars (saves ~250 tokens/call); SQLite search_cache(query_norm, results_json, fetched_at) TTL 1h search / 6h non-news.
- M2. Prompt re-sent in full every call, below any cache threshold; free tier couldn't use caching anyway. Dynamic memory/mood injected mid-prompt breaks prefix caching if ever paid; grudge uncapped shape, style examples 3 long English bullets teach little. Fix: move dynamic sections after static prompt (or into first user message), cap notes+grudge 200 chars each, history 8->6. Saving ~150-250 input tokens/call (~15-20%). Do NOT spend effort on Gemini CachedContent (paid, >=4,096 prefix, hourly fee).
- M3. 7-8 synchronous SQLite connections per chat message, all on event loop (brain/memory.py:7-13 _conn re-runs executescript(schema.sql)+CREATE INDEX every call; handlers _is_duplicate; router quota functions each open own connection). Fix: schema once at startup; one shared connection (or aiosqlite) with asyncio.Lock for BrainRouter+handler; batch get_member+recent_messages. ~7 conns -> 1-2, DB overhead ~50-100ms -> <10ms.
- M4. Voice ffmpeg blocking subprocess.run inside async (tools/voice.py:12-25), Edge TTS no timeout, random voice 12%+25%. Fix: asyncio.to_thread(subprocess.run) or create_subprocess_exec; asyncio.wait_for TTS timeout 15s fallback to text; random voice 12%->5% until latency measured.
- M5. No response cache — repeated questions pay full price (no cache table; pinned_facts/outbox created never used). Fix order: (1) exact-match cache response_cache(normalised_text, intent, reply, created_at) SQLite TTL 1h for chat greetings, never for search/insults; key on normalised text + mood bucket. (2) Later semantic cache with local sentence-transformers >=0.90, measured first.
- M6. Failure modes: Gemini 503 OK but breaker needs 3 visits; Groq 429 bad (C2); DDG blocks -> web_search raises -> grounding "" -> LLM answers ungrounded, may hallucinate, no fallback search provider, no user signal; page fetch fails silently, LLM not told; yt-dlp 300s timeout, no progress, no auto audio-only fallback; Edge TTS fallback good except hang (M4); Telegram 429 on send: _send_text no 429 handling, outer except sends another message which also 429s, outbox table never written; LLM all-fail good in-character but only last_err logged. Fix: second search source (Wikipedia API first, then DDG); video failure auto-retry once audio-only; progress edit ~30s; catch Telegram 429 in _send_text, sleep retry_after, retry once, then write outbox for sweeper; add [SEARCH FAILED] marker so LLM deflects instead of inventing.
- M7. Dead weight: requirements.txt google-genai never imported, tenacity installed but hand-rolled retries, pytest in runtime requirements, yt-dlp unpinned; providers.yaml timeout_seconds/max_retries ignored (router hardcodes timeout 30, 2 attempts), context_messages 8 duplicated hardcoded limit=8; core/config.py log_level ignored (main.py hardcodes INFO); schema pinned_facts/outbox never used; examples.md 6 generic English bullets. Fix: split requirements/dev, pin yt-dlp, delete google-genai or use it, honour config or delete fields, implement outbox/pinned_facts or drop tables; Dockerfile multi-stage, non-root USER, HEALTHCHECK (currently single-stage root no healthcheck).
- M8. Unbounded growth: handlers _last_send/_send_count/_last_user never evicted; bot_data yt_requests never evicted; processed_updates never pruned (1 row/update forever, 365k/year at 1k/day, no index on chat_id/received_at); UUID download folders leak on crash; data/voice likewise. Fix: prune processed_updates >48h on startup+daily; startup sweeper deletes data/downloads/* and data/voice/* >1h; cap in-memory dicts (OrderedDict 1,000); .venv 74MB fine, excluded from Docker, but NOT in .gitignore (only data/ and *.db listed).

## Minor
- m1. Token estimate wrong for Arabic (len//3 undercounts, ~1 token per 1.5-2.5 chars) and used on str(messages) including role/content syntax. Fix: use provider usage when present; fallback len//2 on concatenated content only.
- m2. Reasoning tokens invisible (usage.completion_tokens_details.reasoning_tokens / Gemini thinking never read). Fix: log separately.
- m3. Two sources of truth for temperature (prompt.py temperature_for chat 0.85/search 0.25/youtube 0.4 vs router defaults 0.25 hard/0.7 chat; youtube 0.4 dead because handler returns early). Fix: one table in providers.yaml.
- m4. Typing+voice ordering wastes send: voice then text after upload completes. Fix: send text first, then voice.
- m5. Per-user cooldown silently drops messages (handlers.py:143-147). Fix: reply once per cooldown window "استنى ثانية" (max once per 30s/user), consider per-user daily cap 100/day in /stats.
- m6. Dead imports / dead plugin system (plugins/registry.py only loads list; plugin files never called from handler). m7. No drop_pending_updates decision recorded (main.py:18 run_polling defaults) — after downtime bot chews backlog costing LLM calls. Fix: decide explicitly drop_pending_updates=True on deploy (documented) or startup cap N queued updates then drop.

## Latency budget (estimate, no live LLM call)
Plain chat ~2-7s; search ~4-12s (8-20s with retry); YouTube callback 10-300s no progress. Stages: DB 50-100ms, search 1-6s worst 40s, LLM 2-6s / 3-10s, retry +3-10s, voice +2-5s, send 0.2-1.2s, yt-dlp 10-300s.
Biggest wins: (1) stream + typing refresh, (2) gpt-oss-20b simple chat + Gemini reserved, (3) file_id cache, (4) parallel top-3 fetch + search cache, (5) output cap 400-600, (6) single DB connection at startup.
